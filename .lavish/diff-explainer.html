Ionic mobile client

Six routes cover the authentication lifecycle.

The UI is dark, iOS-first, phone-shaped at every width, safe-area aware, WCAG-oriented, and deliberately excludes food and goal implementation.

What the client adds

  • Passwordless email entry with visible, announced validation.
  • Delivery failure and resend recovery with server-derived countdown.
  • Fragment token exchange with invalid, expired, replayed, and superseded states.
  • Persistent-session startup gate and current-phone sign-out.
  • Development-only state index and generated-link shortcut.
  • 44pt targets, reduced motion, high contrast, and semantic status copy.

Express mock API

The approved HTTP boundary is executable.

The mock uses process memory and cryptographic tokens so interactions can be tested. It does not pretend to be the production SQLite or email implementation.

Why it is compact now

One application module is sufficient for the mock

  • Only one bounded capability: authentication
  • No external persistence or provider adapters
  • Atomic behavior remains easy to inspect and test
Production split point

Extract adapters when real infrastructure arrives

  • Transactional-email provider adapter

  • Route handlers depending on those interfaces
